# Handoff: llama.cpp SM70/SM75 optimization

Date: 2026-09-05

## Objective

Optimize long-context llama.cpp inference for users with:

- NVIDIA Volta SM70, especially Tesla V100-SXM2 32 GB;
- NVIDIA Turing SM75, especially RTX 2080 Ti.

Priority order: prompt processing (PP), time to first token (TTFT), then token generation (TG). Preserve exact output/token behavior and 262,144-token context support where the hardware permits it.

## Main code changes

Existing SM70 stack retained from the original branch:

- Volta 256x256 FlashAttention configuration, including reduced V scratch.
- Adaptive Volta 2-CTA specialization for the exact Qwen geometry.
- Volta scalar-gate GatedDeltaNet x4 prefill path.
- Qwen q8 attention and MTP generation paths.
- Prompt checkpoint/replay and deferred MTP prompt catch-up.
- Volta routed-MoE MMQ guidance.

New shared/backend path:

- Large contiguous host inputs marked as mirrored are submitted through the backend asynchronous setter, followed by one explicit synchronization. This reduces mirrored-copy fan-out overhead while preserving input lifetime. It is not yet proven to overlap those copies with useful compute.

New SM70 paths:

- `GGML_CUDA_VOLTA_GQA8_NCOLS2=2` selects an exact long-K Qwen D=256/GQA8 geometry.
- Volta large-row Q6_K MMQ uses the Pascal DP4A configuration to reduce register pressure.
- `GGML_CUDA_VOLTA_FORCE_MMQ=moe` is an opt-in routed-MoE override; leave it unset for dense Qwen.

New SM75 paths:

- Turing D=256 attention uses smaller prompt tiles for its register/shared-memory balance.
- Turing GatedDeltaNet x4 is enabled for multi-token prefill.
- `GGML_CUDA_TURING_CUBLAS_MIN_BATCH=N` can route large dense Q5_K/Q6_K prompt matmuls to cuBLAS above threshold `N`; it is experimental and unset by default.
- Long-K Qwen GQA6 prompt attention can use `ncols2=2`.
- The exact SM75 D=256, `ncols1=16`, `ncols2=2` attention rescale fast path is guarded in CUDA code.

## What was not established

- No fresh end-to-end SM75 benchmark is published yet.
- The SM75 paths are included and geometry-gated, but their net speedup on RTX 2080 Ti remains unproven.
- The async mirrored-copy code currently submits copies and then synchronizes; useful compute overlap has not been demonstrated.
- No new end-to-end single-V100 A/B run was substituted after the documentation cleanup.
- An attempted one-GPU recheck was invalid: `CUDA_VISIBLE_DEVICES=0` exposed the RTX card rather than the V100, and the f16-KV 262k setup ran out of memory. Do not use its output as benchmark data.
